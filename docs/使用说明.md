# Gungun 使用说明

## 当前版本：从源码运行

当前按要求暂停 DMG 生成和临时 Actions Artifact 上传。Apple Silicon Mac（含 M1 Pro）安装 Node.js 24 和 pnpm 12.23.0 后，在项目根目录运行：

```sh
pnpm setup:install
pnpm prepare:dev
pnpm dev
```

`pnpm setup:install` 自动适配 HTTP_PROXY / HTTPS_PROXY；不需要预装 Go。首次准备会下载并校验项目私有 Go 1.25.4、构建两种 Linux 架构的 fq，以及准备 macOS arm64 sing-box。修改 fq 后运行 `pnpm fq:build`。需要访问 Go 官方下载站和 GitHub 官方 Release。

### 后续安装包

恢复正式发布后，仅提供 Apple Silicon arm64 DMG，不构建 Intel 版本。正式 Release 必须重新通过 DMG 构建、挂载、安装、启动与包内资源验证，并附带 SHA256SUMS。未配置 Apple 凭据时会标明未签名、未公证；源码版测试通过不代表安装包已完成验收。

### 单独安装 fq

Linux 的 x86_64 对应 fq-linux-amd64，aarch64 对应 fq-linux-arm64。当前可使用 `pnpm prepare:dev` 在 `resources/bin/` 生成的对应二进制；后续正式下载应先按 SHA256SUMS 校验，再运行（下例为 amd64）：

```sh
chmod +x fq-linux-amd64
sudo install -m 0755 fq-linux-amd64 /usr/local/bin/fq
sudo fq install
sudo fq core update sing-box
fq version --json
```

这些命令安装程序、服务单元和核心；协议、网站、域名等配置通过 Gungun 部署中心创建。也可使用 fq apply 从 stdin 提交 schemaVersion=1 的配置。Gungun 的“安装 / 更新 fq”会自动识别架构并完成上传和安装，通常更方便。

## 首次设置

1. 在设置填写 Cloudflare 账号邮箱和 Global API Key。问号帮助会说明获取步骤；Key 保留在 Mac，不发送到 VPS。
2. 填写 Let's Encrypt 邮箱。证书申请会接受该服务条款。
3. 在设置生成或选择 Gungun 主 SSH 密钥。
4. 测速默认最大并发 10、Mac 本机、真连接 URL 和下载 URL 可按线路调整。速度单位 MB/s。

本地数据库和导出备份包含敏感凭据，不使用 Keychain。请保护 macOS 用户账号及备份。

## VPS 与 SSH

添加主机时手动选择公网 / NAT，填写服务器地址、SSH 端口、用户名和服务商提供的 SSH 密码。节点对外地址默认与服务器地址相同；只有 NAT 映射或独立对外入口时才单独填写。可以从已有主机选择跳板机。如使用 Tailscale，服务器地址填可达的 Tailscale IP。系统不会替你自动加入 Tailscale 网络。

测试失败仍可保存。首次连接会在测试结果区域显示 SSH SHA256 指纹；通过服务商控制台等可信渠道核验后，直接点击「信任指纹并继续测试」，Gungun 会保存信任并自动重新执行连接测试，无需打开命令行或手动再次测试。使用跳板机时，跳板机与目标主机分别核验；若某一台首次连接，信任后会自动重试完整连接流程。已信任主机的指纹若发生变化，会明确提示并要求重新核验，只有用户确认后才更新信任。密码登录成功后，在 VPS 详情点击“安装 SSH 主密钥”；Gungun 将公钥追加到 authorized_keys，并实际验证密钥登录。只有验证成功才会切换为密钥认证并清除本机保存的 SSH 密码。VPS 详情可打开 SSH 终端、查看状态、生成独立 SSH config。

选择安装 / 更新 fq，任务中心显示 CPU 识别、上传、服务安装和核心校验。支持 Linux amd64 / arm64、systemd。非 root 用户需预先配置无交互 sudo。不会修改用户的现有 SSH config。

## 部署协议

每台 VPS 的独立 namespace 在创建时自动生成并固定，无需手动填写。首次部署需要域名的协议时，在部署中心读取并选择 Cloudflare Zone；选择后会绑定到该 VPS，后续部署可复用。Cloudflare API 凭据在设置中配置。

进入部署中心，选择 VPS，再选择六种协议之一。公网 VPS 的端口填 0 可自动分配；NAT 必须填写内部监听和服务商已映射的公网端口，不支持端口跳跃。除 Snell 和 Reality 外，普通 TLS 服务需要申请证书。

VLESS + WS 可选择直连、Cloudflare CDN 或 Argo Tunnel。直连、CDN、Argo 共用一个内部监听端口，不再为每种接入方式重复填写内部端口。NAT 场景下，公网映射端口默认等于内部端口；只有服务商分配的公网端口不同时，才开启“公网映射端口不同于内部监听端口”单独填写。其他协议仍按各自服务配置监听端口。

CDN 可选择客户端到 Cloudflare 的 HTTP 或 HTTPS：HTTPS 默认 Edge 443，HTTP 默认 Edge 80，并可选择 Cloudflare 支持的其他 Edge 端口。Edge 端口是客户端连接 Cloudflare 的端口，不是 VPS 内部监听端口。公网映射端口是 Cloudflare 回源到 VPS 时使用的端口；NAT 服务商再负责将公网映射端口转发到内部监听端口。

例如 Edge HTTPS 2053、公网映射 18880、内部监听 45516：Gungun 创建 Origin Rule，将目标端口改为 18880；NAT 服务商将 18880 转发到 45516。若 Edge 端口与公网映射端口相同，则不需要端口覆盖规则；若不同，规则目标始终是公网映射端口，而不是 NAT 内部端口。NAT 内部端口转换由服务商处理。

切换 CDN HTTP / HTTPS 只改变客户端访问 Cloudflare 的协议和 Edge 端口，不改变 VPS 的共享监听端口。Gungun 的 VLESS + WS 源站监听使用 TLS；Cloudflare Zone 的 SSL/TLS 模式应允许 HTTPS 回源，使用 Full 或 Full (strict)，不要使用 Flexible。Argo 也复用同一个内部监听端口，并通过 HTTPS 回源到 VPS 的 TLS 监听器。

HTTPS CDN 和 Argo 会检查 Cloudflare Edge 证书覆盖；HTTP CDN 不要求客户端到 Edge 使用 TLS 证书，但 VPS 源站仍需要自己的 TLS 证书。多级建议域名尚无 Edge 覆盖时，自动生成的名称会改为 cdn-namespace.zone / argo-namespace.zone；自定义多级域名则明确提示先在 Cloudflare 配置覆盖，不会自动购买付费服务。VPS 的泛域名证书继续保留，必要的一级服务域名加入其 SAN。

Argo 每 VPS 一个固定 Tunnel，内部使用 HTTP 回源，不需 VPS 公网监听 80 / 443。同步后会出现 443 TLS 和 80 HTTP 两个客户端节点。Tunnel 只有 HTTP / WebSocket 接入能力，不能用它承载 Hysteria2 / TUIC 的普通 UDP 服务。

Reality 使用握手目标和密钥，不需要普通 TLS 证书。UDP 协议需要服务商与系统防火墙实际允许 UDP，软件无法替代服务商端口开放。

## 网络服务与网站

网络服务选择 VPS 后读取 fq 配置。可检查状态、更新核心、打开实时日志、重启和删除服务。每个远程变更都生成备份并预检查，失败自动回滚。

网站填写域名、目标 IP、目标端口和 HTTP / HTTPS 回源。目标可运行在 3000、5201、8080、9000 等端口。Caddy 负责反向代理；公网默认直连，NAT 填已有公网映射，没有可用入站可选 Argo。网站域名必须属于所选 Cloudflare Zone；Gungun 申请证书并配置 DNS。HTTPS 回源需要上游证书有效。多个 HTTPS 网站可以共用内部监听端口；Argo 的内部 HTTP 与 HTTPS 网站需要使用不同内部端口，否则预检查会拒绝。

WARP 页面安装并连接服务器 WARP，然后在协议部署中选择 WARP 出站。只影响该协议，默认 DIRECT；不会修改 SSH 的全局路由。Cloudflare 的 WARP 包对系统版本有要求，不支持的系统会明确报错。

备份页面可创建备份、读取列表和恢复指定版本。恢复前仍备份当前状态，并校验备份完整清单和 SHA256；损坏或未完成的备份不会覆盖正在使用的配置。删除网站时保留 DNS，避免误删可能被其他服务使用的记录。

## 节点、订阅与聚合

VPS 详情点击“手动同步节点”，通过 SSH 调用 fq export。每 VPS 有独立 Tag；重新同步以 VPS 数据为准，覆盖本地对 VPS 节点的编辑。外部订阅使用“新建分组 → 外部订阅”，填 URL 后手动更新。手动导入支持分享链接、Base64、Mihomo YAML。

所有节点是虚拟分组。新建动态聚合时勾选多个 Tag；它们的节点会动态映射，不复制数据。同一 Tag 可加入多个聚合。

节点左键选中整行，双击查看不同测试主机的最新结果，右键 / 三点菜单编辑、测速、优选或删除。删除原始节点前会列出受影响链路，确认后一起删除。远程同步或订阅更新导致原始节点消失时会清理对应链路。

导出提供 V2Ray Base64 和 Mihomo YAML。Snell v6 及代理链不能用普通 V2Ray 分享格式完整表示，必须使用 Mihomo。导出文件包含节点凭据。

## 链式代理

进入独立“链式代理”Tag，创建链路，选择第一跳和最终出口。顺序表示 Mac → 第一跳 → 第二跳 → 最终目标；可上移 / 下移，也可扩展多跳。节点按 ID 引用，参数修改后自动读取最新值。

当前支持后续 TCP 拨号的 VLESS、AnyTLS、Snell 等组合；第二跳及以后 Hysteria2 / TUIC 需要 UDP 拨号，暂明确阻止。保存后执行测试；详情显示每一跳连接、错误、最终结果和完整链路下载速度。前一跳失败时，后续跳显示“未测试”，请先解决上游连接。不能只看单节点延迟判断整链可用。

用 Mihomo 导出链路时保留各跳 dialer-proxy 关系。链路不是一个可以直接粘贴到普通 V2Ray 订阅中的虚假链接。

## 测速与优选 IP

两个批量按钮分别测试真连接延迟和多线程延迟 + 速度，范围严格为当前 Tag。测试源可选 Mac 和其他 VPS，多选会对每个来源分别执行。自动排除 VPS 测试自身节点及包含自身节点的链路。列表的“显示来源”决定展示哪台主机结果；详情显示全部来源。

只有每个来源的最新结果，没有复杂历史曲线。进程启动时间不计入代理延迟；下载速度受候选线路、远程出口和下载站点共同影响，不保证跑满本机带宽。

CDN / Argo 节点的优选 IP 页面可以获取 Cloudflare 候选或手动填写。测试时只替换 Address，保持域名、SNI、路径和认证参数。点击“应用”后更新本机节点，不修改 VPS。候选 IP 仅从官方网段取样，不代表保证最佳线路。

## fq 命令

```sh
fq
fq status --json
fq list --json
fq log gungun-sing-box
fq restart --json
fq update v1.0.0
fq core update sing-box
fq warp status
fq warp install
fq backup
fq backup list
fq restore BACKUP_ID
fq export --json
fq uninstall --yes
```

`fq uninstall --yes` 停止并移除 Gungun 服务单元，默认保留配置和备份；加 `--purge` 才删除配置。第三方 core 和 fq 二进制不自动清除，避免删除可能仍在使用的文件。`fq update` 依赖可公开下载的 Release；私有仓库建议通过 Gungun 的 SSH 上传更新。

## 常见问题

- SSH 指纹未知 / 已变：独立核验后信任，不能跳过校验。
- sudo -n 失败：使用 root 或由管理员设置所需权限。
- UDP 协议失败：检查服务商 UDP、安全组、防火墙、映射以及回程。
- CDN 失败：按“客户端 Edge 端口 → Origin Rule 目标公网映射端口 → NAT 服务商转发 → VPS 内部监听端口”逐段核对。Origin Rule 目标填写公网映射端口，不填写 NAT 内部端口；Edge 与公网映射端口不同时才需要端口覆盖规则。检查 Cloudflare 支持端口、Zone SSL/TLS 模式和 DNS。
- Argo 失败：检查 cloudflared 日志、Tunnel ingress hostname 及服务商到 Cloudflare Tunnel 的出站网络。
- 证书续期：Mac 必须在线且可 SSH。应用每日检查；长期离线前手动续期。
- 配置回滚失败：保留任务错误与 backup ID，SSH 使用 fq restore 恢复，不要反复覆盖状态。


## 外观设置

设置 → 外观 → 应用主题，可选择“跟随系统”“浅色”“深色”，保存后立即应用到所有窗口并在下次启动恢复。默认跟随 macOS 外观变化。

所有实际协议测试与链式代理执行均由 sing-box 完成。Mihomo 是导出的 YAML 格式，无需安装 Mihomo。外部节点若带整张证书 SHA256 pin，sing-box 无法原样验证，会明确阻止测试；请使用可信证书或确认节点验证参数，程序不会自动关闭验证。

当前执行核心兼容性：Hysteria2 / TUIC 直接接 VLESS WS / Reality 的四种组合在真实下载回归中不稳定，暂时明确拒绝创建和执行。可使用 AnyTLS / Snell 作为中间跳，或选择 TCP 第一跳。已支持的组合需通过实际连接和下载；能力拒绝测试与真实连通测试分别计数，不把拒绝当成连通成功。


## Cloudflare 独立资源管理

从一级导航打开 **Cloudflare**。沿用设置中的邮箱和 Global API Key，不重复录入；密钥不会写入 VPS。顶部选择账号和 Zone，然后按资源标签操作。刷新会重新读取 API；权限错误直接展示，不以空列表或虚构证书代替失败。

- **DNS**：支持 A、AAAA、CNAME、TXT、MX、NS；查看其他类型，SRV / CAA 的结构化编辑请使用官方控制台。可以搜索名称 / 内容、筛选类型、修改 TTL 和橙灰云。TTL `1` 表示自动。标有 `Gungun managed` 备注的记录视为 Gungun 管理；旧版本无标记的记录保守归为外部。修改外部记录需要勾选确认；如要供后续部署使用，可明确勾选接管，写入归属备注。删除有单独确认，删除 VPS / 服务不会删除 DNS。
- **Tunnel**：显示当前账号 Tunnel、在线状态、ID、创建时间和关联 VPS。查看 ingress 的域名及目标地址；外部 Tunnel 只读。Gungun 路由可修改本机目标、删除并恢复缺失路由；仅允许操作已关联节点或已记录的部署路由，不能接管未知路由。带路径的外部路由不会被批量覆盖。路由目标是 **VPS 内部** 的 `http(s)://127.0.0.1:端口`，不是 Mac 的端口。路由调整不会自动修改 DNS 或远程监听，后续重新部署会按 VPS 配置重新协调已管理路由。
- **Edge 证书**：展示 API 实际返回的 Universal SSL 状态、证书包、覆盖域名和有效期；没有有效期就显示 API 未提供。输入完整域名检查生效证书覆盖。`*.example.com` 覆盖 `cdn.example.com`，不覆盖 `cdn.abcde.example.com`。API 权限受限时明确提示；不自动购买证书。覆盖检查不替代 DNS、Tunnel 和源站连接测试。
- **Origin Rules**：增删改、启停、匹配表达式、回源公网端口与优先级。与部署中心使用相同域名 ref，修改单条规则不会重建整套规则。外部规则需额外确认；资源在刷新后发生变化时，先刷新再重新确认。

三个端口需要分别核对：

| 位置 | 示例 | 设置位置 |
| --- | --- | --- |
| 客户端到 Cloudflare 的 Edge HTTPS 端口 | 2053 | 节点接入参数；普通 HTTPS 默认 443，HTTP 默认 80 |
| Cloudflare 到 VPS 的公网映射端口 | 45516 | Origin Rule 的目标端口 |
| VPS 内部 sing-box / Caddy 监听端口 | 45516 或其他实际内部端口 | 部署中心、VPS 和 NAT 映射 |

Origin Rules 编辑窗口中的 Edge / 内部端口仅用于核对链路，不会假装修改 Cloudflare Edge 监听或 NAT 映射。真实写入规则的是回源目标公网端口。

## Mac 本机代理与系统代理

本机 sing-box 与 VPS 上的 sing-box 进程、配置完全独立；使用本机代理不需要 SSH 启动远程核心，也不改远程节点配置。

1. 设置 → 本机代理 → **下载 / 检查本机核心**。固定 1.14.4，下载校验 GitHub 官方 SHA256，缓存于应用私有目录，优先复用有效的随应用核心。
2. 节点或链路右键 → **设为活动节点 / 链路**。未运行时只保存选择；已运行时先检查新配置，在临时端口验证真实代理请求，之后切换正式端口。切换失败尝试恢复旧配置与活动节点。链路始终读取原节点 ID 引用，禁止的 UDP / 不稳定组合仍明确拒绝。
3. 底栏播放按钮启动本机核心，停止按钮停止并在需要时恢复系统代理。mixed inbound 兼容 HTTP / SOCKS，默认 `127.0.0.1:10808`。不启用系统代理时，其他应用可手动使用此端口。设置端口前必须停止本机核心。
4. 使用系统代理前，在已签名的 Gungun.app 中点击设置里的 **安装 / 授权系统代理辅助程序**，按 macOS 系统设置 → 通用 → 登录项与扩展完成批准。macOS 13 及以上受支持，首次批准由系统处理，不记录管理员密码。源码 `pnpm dev` 不会绕过系统注册与签名要求。
5. 底栏点击 **开启系统代理**，选择当前活动 Wi-Fi / USB LAN 服务。先确认本机核心正常，再备份并设置此服务的 HTTP、HTTPS、SOCKS，暂时关闭 PAC / 自动发现。只修改选定服务。
6. **关闭系统代理** 会恢复完整原快照，包括地址、端口、PAC URL / 开关、自动发现和绕过列表，并检查结果。单独播放启动的核心会继续运行；系统代理临时启动的核心在成功恢复后停止。

异常时：

- 配置错误、端口占用或新节点请求失败时，尽量保留当前正常代理；失败信息与脱敏日志可在底栏查看。
- 原 PAC 已开启但 URL 不可读时拒绝覆盖；先在 macOS 系统设置核验 PAC，不能跳过备份。
- 原生辅助程序保存 root 专属恢复日志，监测应用心跳和监听端口；应用崩溃、重启或失去心跳后尝试恢复，辅助程序重启也先处理日志。正常情况下按 2 秒检查、10 秒租约过期处理；真机时延待验收。
- 网络服务切换时恢复原选中服务，不擅自修改新服务；为新活动服务重新开启即可。
- 检测到用户 / 其他应用修改代理时停止自动覆盖，底栏显示冲突。先在系统设置核验 HTTP、HTTPS、SOCKS、PAC 全部字段，再到 Gungun 设置明确解除旧恢复记录；解除只放弃旧记录，不改当前系统配置。混合修改可能留下仍指向本机的部分字段，需要人工核验。
- 恢复或回滚失败会保留原因和恢复记录，不会显示恢复成功。

本轮只实现系统代理，未实现或展示 TUN 开关。本机系统代理流程尚需真实 Apple Silicon macOS 验收，不能把界面可用或模拟测试通过等同于系统接管成功。

### 网络服务下拉框为空（修复记录，2026-11-28）

网络列表及代理状态的只读查看与特权写入分开：源码开发模式也可查询 Wi-Fi、USB LAN 等服务，无需先安装 / 授权特权程序。列表显示当前默认网络路由对应的活动服务；IPv4 未找到时查询 IPv6，不猜测第一个服务为活动服务。

读取失败会在设置或选择窗口直接显示原因，并提供刷新；无服务、无活动连接和加载中分别提示，不显示内部 `__gungun_empty_option__`。查询仅读取系统配置，不会修改 HTTP / HTTPS / SOCKS / PAC。真正开启 / 恢复系统代理仍需已安装并获准运行的签名应用辅助程序；开发模式不能因此直接修改系统代理。
